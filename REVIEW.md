# Reviewing MergeLoop

`AGENTS.md` and `CONTRIBUTING.md` state the conventions. This file says what goes wrong here.

## What failure looks like

- **A prompt tells the agent something the code does not do.** The prompts in
  `crates/resolver/src/lib.rs` and the briefs in `crates/mergepatrol/src/` are instructions to
  an agent. A sentence that names a file, command, tool or JSON key the code does not provide
  is a bug, as is one that contradicts another prompt.
- **The docs lie.** `README.md` is the docs site (`crates/web/src/docs.rs` cuts it into pages).
  A change in how the queue, review or settings behave that leaves a README sentence untrue is
  a bug in the PR, not a docs follow-up.
- **The API and the dashboard drift.** A dashboard feature without its route in `ROUTES` and its
  `tool!`, or a route whose tool description and `args` no longer match it.
- **A user-visible change ships without its `content/changelog/` entry.**

## Skip

- `ui/src/api/`: generated by `cargo test` from the Rust types. Review the Rust type instead.
- `Cargo.lock` and `ui/pnpm-lock.yaml`, beyond which packages a PR adds or bumps.

## Small findings

Report at most three style or naming findings, and none on wording that is clear enough.
